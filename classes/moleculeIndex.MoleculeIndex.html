    Class MoleculeIndex

    The in-memory search engine over a store's file: the tiles loaded into bit planes, grouped by atom count and band, followed through the commits; substructure searches, browse and similarity answered in pages with a cursor, every page by its deadline. The application hands it, as SQL, its order key, its filter columns, its id sets and its change log.

    count

    • count(options?: CountOptions): Promise<Counts>

      Counts the molecules a browse with these options answers, in the search workers: the sets, the keys, the filter columns and the key bounds are all held in memory, so no row is read from SQL (but the rare tied value of a filter, as in a search). The tallies come from the same pass. It runs in chunks, each a turn of its lane, so an interactive search waits for one chunk at most.

      Parameters

      • options: CountOptions = {}

        The restriction and the tallies; lane defaults to 'bulk'. budgetMs counts from the first chunk's start, and signal stops it.

      Returns Promise<Counts>

      The counts; complete is false when the budget or the signal stopped it.
